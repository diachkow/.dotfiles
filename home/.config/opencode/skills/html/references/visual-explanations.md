# Visual explanations

Use this when a system, process, idea, or comparison will be easier to understand when people can see how its parts fit together.

Start with a specific reader question, such as "What happens after this event?", "Why did latency rise?", or "How do these options differ?" Pick one main idea and organize the page around it. Useful forms include:

- an annotated diagram for components, boundaries, and relationships;
- a sequence or timeline for events and causality;
- a before-and-after view for changes;
- a side-by-side comparison for alternatives;
- an interactive walkthrough when revealing or stepping through detail helps comprehension.

Use the source's real terminology and examples. Separate facts from interpretation, and label simplifications, assumptions, and illustrative values. Keep the overview visible; put supporting detail nearby or behind an explicit, keyboard-accessible disclosure. Avoid interaction that adds clicks without improving understanding.

Check that the main point is apparent without animation, labels remain readable on narrow screens, and the visual doesn't imply relationships or certainty the source does not support.
