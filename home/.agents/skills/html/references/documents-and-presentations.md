# Documents and presentations

Use for reports, briefs, and slide-like artifacts. For visual explanations centered on a concept or system, also read [`visual-explanations.md`](visual-explanations.md).

## Documents

Design around what the reader needs to understand or decide, not a generic outline. Orient the reader quickly, then place evidence and detail in the order they need it.

- Keep prose measures readable; let tables, code, timelines, and diagrams use wider regions.
- Use headings, labels, numbering, dividers, and callouts only when they express real hierarchy or sequence.
- For reports, distinguish observation, interpretation, recommendation, and uncertainty.
- For comparisons, align like-for-like attributes.
- For explainers, move from the reader's question to the relevant model, then show evidence or examples.
- Add print styles when printing is a real use case; keep essential content visible without interaction.

## Presentations

Give each screen one job and one dominant idea. Establish a consistent rhythm, then break it only for emphasis. Keep essential information visible without hover. Use keyboard navigation and direct slide links when practical, and use transitions to explain order rather than decorate every change. Provide a useful narrow-screen or scrolling fallback.

When a request mixes a document and deck, choose the reading mode the audience will use instead of building two partial experiences.
